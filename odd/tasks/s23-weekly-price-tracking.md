# S23 Weekly Price Tracking
Objective: Add weekly refurbished Galaxy S23/S23 FE offer collection, saved price history, interactive price charts, and a sourced chipset comparison.
Branch: `feat/s23-refurbished-price-tracking` | Delivery strategy: `local-only` (user-directed; no GitHub publish or PR) | Runner: Python `unittest` and Node checks.

## Specs

### S1 — Refurbished offers and budget bands
User requirement: “Me interesa que sean reacondicones y ofertas que esten dentro del rango y como margen de unos $30.000”
Accepted budget interpretation: “Tope $340k + alerta hasta $370k”.
Acceptance: Include only clearly identified refurbished Galaxy S23 or S23 FE offers; mark prices through CLP 340,000 as within budget, CLP 340,001–370,000 as near budget, and exclude higher offers. Do not silently treat merely used/seminuevo items as refurbished.
Check: Unit tests cover refurbished classification and exact lower/upper budget boundaries.

### S2 — Weekly source collection
User requirement: “Hay una manera de tener una api o alguna manera de poder obtener la informacion actualizada cada semana y con un histograma de precios. Para ir viendo desde la misma pagina como se va actualizando el precio/”
User source preference: “Si hay una api gratuita seria genial. Lo que no se es como podriamos hacer un scrapping desde la web raiz y desde hay que se realize una busqueda interna del dispositivo.”
User local-only correction: “Cancelar revision y solo realizar el proyecto ya que no e algo que se subira a github, solo estara local”
Acceptance: Keep the project local; provide a weekly local scheduler (cron), not GitHub Actions or automatic remote commits. Use each merchant's published supported product-discovery interface and preserve dated snapshots. Do not bypass authentication, anti-bot controls, access restrictions, or merchant-published agent interfaces. Reuse and Bodega Oportunidades publish UCP profiles with MCP `search_catalog` tools; anonymous MCP initialize and tools/list succeeded. The MCP call requires a truthful public UCP agent-profile URL. The project includes a profile file but must not pretend a local URL is public; no live collection can run until the user supplies a reachable HTTPS profile URL. Store no credentials in browser code or price history.
Check: Mocked source tests validate UCP request parsing, product normalization/filtering, failure isolation, and unchanged history on rejected/invalid data; a single live read-only UCP catalog search confirms selected sources only when the agent profile requirement can be satisfied.

### S3 — Price-history visualizations
User requirement: “con un histograma de precios. Para ir viendo desde la misma pagina como se va actualizando el precio/”
Acceptance: Show historical price movement over time and the distribution of currently observed offers, with accessible labels and the dataset's actual last-update time. Preserve a historical record rather than overwriting old observations.
Check: Validate chart rendering from fixture data and empty-history behavior; verify responsive and reduced-motion behavior structurally.

### S4 — Processor and buying comparison
User requirement: “Tambien podriamos agregar diferencia entre el procesador que viene, ya que pasa si viene con un exynos y no el snapdragon. Cual combiene segun el precio y en potencia, duracion de la bateria. Seria bueno saber esas cosa para tener en cuenta y no solo el precio.”
Acceptance: Explain that S23 uses Snapdragon 8 Gen 2; S23 FE differs by region (Exynos 2200 or Snapdragon 8 Gen 1), label a listing's chipset only when the source/model confirms it, compare measured performance and battery evidence with source links, and explain that refurbished battery condition can dominate real-world runtime. Recommend model/variant value in context of observed prices without inventing an undisclosed battery-health value.
Checks: Source links are included in the UI; variant mapping and unknown-model behavior are tested; human-readable recommendation distinguishes benchmark evidence from expected real-world results.
